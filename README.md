# DDIP Web

**DDIP**은 크라우드펀딩(프로젝트 모금)과 **실시간 경매**를 한 서비스에서 제공하는 플랫폼입니다. 팀은 **FE 1명(본인), BE 2명**으로 진행했고, **프론트엔드는 제가 단독 담당**했습니다. 사용자·창작자·관리자가 실제 업무 흐름으로 이용할 수 있도록 화면·상태·API 연동을 구현했습니다.

백엔드 REST API, 이미지(S3), 인증 토큰과 연동하는 구조입니다.

## 서비스 한눈에

- **크라우드펀딩**: 프로젝트를 등록하고 리워드(티어)를 구성한 뒤, 후원자가 금액을 모으며 목표 달성까지 진행 상태를 확인합니다.
- **경매**: 경매를 등록·수정하고, 참여자는 입찰·내역 조회를 하며 필요 시 **실시간 입찰 반영**(WebSocket/STOMP)을 사용합니다.
- **운영**: 관리자는 사용자·프로젝트·경매를 검토하고 승인·거절 등 조치를 할 수 있습니다.

## Key Challenges

기존 구현에서 반복해서 다루던 인증, 명세 정합, 실시간 입찰, API 레이어 이슈를 아래 네 가지로 정리했습니다.

### 1. 동시 401 Refresh Token 중복 처리

**문제**

Access Token이 만료되면 여러 API 요청이 동시에 401을 받을 수 있습니다. 각 요청이 따로 Refresh를 호출하면 토큰이 꼬이거나, 세션 종료 타이밍이 요청마다 달라집니다.

**해결**

HTTP 클라이언트(`apiClient`)에서 Refresh를 **하나의 Promise lock**으로 묶었습니다. 동시에 401이 나더라도 Refresh는 한 번만 수행하고, 대기 중인 요청은 그 결과를 공유합니다. 새 Access Token이 오면 원 요청을 **1회만 재시도**하고, Refresh 실패 시에는 세션을 정리한 뒤 인증 Context와 맞춰 로그아웃합니다. Refresh는 HttpOnly 쿠키로만 다루며, 비로그인·세션 힌트가 없으면 호출 자체를 생략합니다.

**결과**

만료 직후의 병렬 요청에서도 Refresh가 중복되지 않고, 재시도·세션 종료 경로가 한곳으로 모입니다. 토큰 갱신/재시도는 클라이언트, 로그인 상태 반영은 인증 Context로 역할을 나눠 끊김 없는 이용과 명확한 로그아웃을 같이 맞췄습니다.

### 2. Swagger/OpenAPI 타입 자동화

**문제**

백엔드 명세와 프론트 수동 타입이 따로 움직이면 경로·필드 불일치가 화면까지 번집니다. 팀 백엔드가 명세를 고치는 동안 프론트는 이행 기간에도 빌드를 유지해야 했습니다.

**해결**

백엔드 Swagger(OpenAPI) 문서를 `openapi-typescript`로 받아 타입을 생성하고, DTO 이름은 프론트에서 쓰기 쉬운 alias로 감쌌습니다. 기존 화면/서비스가 의존하는 수동 타입은 바로 제거하지 않고 **생성 타입과 병행**해, 명세가 안정되는 동안 호환을 유지했습니다.

**결과**

API 경로와 응답 형태를 Swagger 기준으로 맞출 수 있고, 스크립트로 타입을 다시 생성할 수 있습니다. 생성 타입과 수동 타입을 함께 두어 이행 기간에도 화면 코드를 한 번에 갈아엎지 않았습니다.

### 3. STOMP/WebSocket 실시간 경매

**문제**

경매 상세에서는 다른 참여자의 입찰과 종료 상태가 늦게 보이면 현재가·내역이 어긋납니다. 입찰 전송까지 소켓에 실으면 실패 처리와 REST 권한 검증이 겹칩니다.

**해결**

수신만 STOMP over WebSocket(`@stomp/stompjs`)으로 처리하고, 입찰 요청 자체는 REST로 유지했습니다. 경매 상세에서는 해당 경매 토픽을 구독하고, 같은 토픽의 입찰/종료 메시지는 payload 구조로 구분합니다. 연결은 인증 완료 후에만 열고, 재연결 횟수 상한과 환경 변수로 비활성화를 둘 수 있게 했습니다.

**결과**

타인 입찰이 현재가·입찰 내역 UI에 바로 반영되고, 입찰 전송 실패는 REST 응답으로 처리합니다. 소켓은 구독/재연결/메시지 구분에 집중하고, 입찰 권한·검증은 REST 경로를 그대로 사용합니다.

### 4. API Service 구조 개선

**문제**

API 호출이 단일 대형 파일에 모여 있으면 검색·리뷰 범위가 커지고, 도메인 변경이 관계없는 함수까지 건드리는 형태가 됩니다. 이미 많은 화면이 같은 import 경로를 쓰고 있어 파일만 쪼개면 import가 깨집니다.

**해결**

크라우드·경매·사용자/인증/배송지·관리자·검색을 **도메인별 서비스 모듈**로 나누고, 공통 HTTP는 `apiClient`로 모았습니다. 중앙 `api.ts`는 구현을 두지 않고 **re-export 중심의 얇은 허브**(약 74줄)로 남겨, 기존 import 경로를 유지했습니다.

**결과**

도메인 변경 범위가 해당 서비스 파일로 줄고, 허브는 진입점만 담당합니다. 화면 코드의 import 경로를 일괄 수정하지 않고도 레이어를 나눌 수 있었습니다.

- **토큰 관리**: Access·Refresh 저장 및 만료 시 갱신·재요청 흐름(401 기준, 세션 만료 시 일관 로그아웃)

### 크라우드펀딩(프로젝트)

- **목록**: 전체 프로젝트 페이지, **무한 스크롤**(Intersection Observer, 미리 로드 여유)
- **필터·정렬**: 진행 상태(전체·진행·성공·실패·취소 등), 정렬(최신·인기·마감 임박·모금액 등) — **Zustand + localStorage**로 새로고침 후에도 유지
- **상세**: 프로젝트 소개·리워드·후원(펀딩) 참여

- **후원(펀딩)**: 리워드 선택 후 후원 요청, **내 후원 내역** 조회. 수량·금액 계산이 무거운 입력은 **지연된 파생 값**으로 분리
- **배송지**: 후원 시 **다음 우편번호 검색**(Daum 우편번호) 연동
- **찜하기**: 프로젝트 카드 하트, 위시리스트 저장
- **상태 표시**: 실패·취소·일시정지 등 운영 상태에 맞는 배지·구분 UI

### 경매

- **목록**: 전체 경매 페이지, **무한 스크롤**
- **필터·정렬**: 경매 상태(예정·진행·종료·취소 등), 정렬(최신·가격·마감 임박·입찰 수 등)
- **상세**: 현재가·입찰 UI·입찰 내역, **실시간 입찰 목록** 컴포넌트(WebSocket 훅과 연계)
- **생성·수정**: 멀티파트·이미지·검증
- **입찰**: 입찰 요청, **내 입찰 내역**, 경매별 입찰 내역 조회
- **찜하기·알림**: 경매 카드 찜, **찜한 경매 모니터링**(전역), 시작·종료 등 알림·중복 방지·가시성(탭 포커스) 고려
- **검색 연동**: 통합 검색에서 경매 검색 API 사용

### 검색

- **통합 검색 페이지**: 프로젝트·경매를 한 화면에서 검색
- **필터·정렬**: 목록 페이지와 동일한 필터 스토어 연동
- **빈 결과·복구**: 한쪽 API가 실패해도 다른 쪽 결과는 노출

### 마이페이지

탭으로 구성된 **내 활동 허브**:

1. **내 프로젝트** — 내가 만든 펀딩 목록
2. **내 경매** — 내가 연 경매 목록
3. **후원 내역** — 후원한 프로젝트
4. **입찰 내역** — 입찰한 경매
5. **찜한 항목** — 찜한 프로젝트·경매

URL 쿼리로 특정 탭(예: 찜한 항목) 진입 지원.

## Development Process

UI 초안과 반복 구현에는 v0·Cursor를 **설계·구현 보조**로 활용하고, 생성된 코드는 직접 검토·수정했습니다. 핵심 시간은 인증, 실시간 동기화, API 정합, 성능처럼 설계 판단이 필요한 구간에 썼습니다.

## Getting Started

```bash
cd front
npm install
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)으로 접속합니다.

백엔드 URL·환경 변수는 팀 설정(`.env` 등)을 따릅니다. 자주 쓰는 값은 아래와 같습니다.

| 변수 | 역할 |
|------|------|
| `NEXT_PUBLIC_API_BASE_URL` | REST API 베이스 URL (기본값 `http://localhost:8080`) |
| `NEXT_PUBLIC_WS_URL` | STOMP WebSocket URL (기본값 `ws://localhost:8080/ws`) |
| `NEXT_PUBLIC_ENABLE_WEBSOCKET` | `false`면 웹소켓 비활성화 |

타입 생성·기타 스크립트는 [`front/README.md`](./front/README.md)를 참고하세요.
